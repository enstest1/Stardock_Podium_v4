# 12 — Test Plan and Acceptance Criteria

**PROPOSED**, except where a result is marked OBSERVED.

## 1. Three kinds of evidence — never mixed

| Kind | Examples | Who decides | May gate automatically? |
|---|---|---|---|
| **Objective consistency** | A quote exists in a line; a promise has a payoff; an SFX starts on a sample; loudness is −16 LUFS | Python | Yes |
| **Model-judged claims** | "Do these lines pay off this clue?"; "Which outline is better?" | LLM judges, two families, both orders | Only single-claim yes/no checks; preferences advise |
| **Human judgment** | "Is this a good episode?" | A person | Approval and publishing |

No automated score in this plan is a measure of how good a story is. Pairwise results are reported as win counts with the number of judgments and the judge models; they are never averaged into a single "creativity score".

## 3. The fourteen tests

Each has: purpose · procedure · objective pass criteria · a passing example · a failing example that the test must catch.

### T01 — Eight-episode season planning
- **Procedure:** stub planner returns `roadmap_8.json`; `create_season` validates and writes. **[LIVE]** variant: real planner, 3 runs.
- **Pass:** 8 milestones numbered 1–8; question and opposition non-empty; 2–4 locked commitments each referenced by a milestone; roles — `inciting` ≤ episode 2, `midpoint_reversal` in 4–5, `low_point` in 6–7, `climax` in 7–8; every main character has a focus episode; every mystery clue scheduled before its payoff; no three identical `obstacle_type` in a row; ≥ 2 non-central episodes.
- **Passing example:** the fixture roadmap.
- **Failing example:** `bad_no_midpoint.json` → validator lists "no midpoint_reversal between 40% and 60%"; `bad_clue_after_payoff.json` → "clue K2 scheduled in episode 7 after payoff in episode 6".
- **Subjective (advisory):** human reads the roadmap; notes go in the report.

### T02 — Three consecutive completed episode scripts
- **Procedure:** **[LIVE]** `produce-episode` for episodes 1–3 of the fixture show with `USE_SCENE_CARDS`, `USE_CANON_LEDGER` on, auto-approve.
- **Pass:** each episode has 5–14 scenes with cards; every scene prompt after the first contained the previous hand-off (from the trace); zero lint errors after at most one revision round; zero "and then" links; episode 2 and 3 planner contexts contain ≥ 1 canon event from the previous episode; extraction reports show 0 unverified records in the ledger; frameworks of the three episodes are not all the same.
- **Failing example:** legacy pipeline on the same inputs → no cards, fixed 17 scenes, hand-off absent (the test asserts the legacy arm fails these criteria, proving they discriminate).
- **Subjective:** blind pairwise, legacy vs new, per episode slot (doc 07 §7).

### T03 — Character-specific knowledge accuracy
- **Procedure:** run extraction + belief derivation on `scripts/ep1–3.json` (stubbed extractor for the unit test; **[LIVE]** for accuracy). Then ask 20 fixed questions of the form "As of the end of episode N, does character X know/believe P?" answered by SQL.
- **Pass (unit):** all 20 match the annotations. **Pass ([LIVE]):** belief precision ≥ 0.90 and recall ≥ 0.80 against annotations (targets, **UNVERIFIED** as achievable — record the measured values and adjust).
- **Passing example:** "Does Mara know Ilen sent the reply (end of ep 3)?" → No; she `believes` the false proposition "array fault", `source=deceived`.
- **Failing example:** `negatives/omniscient_ep3.json`, where Dace says "You sent it, Ilen" with no scene in which she learns it → `omniscience_check` must raise one error on that line.

### T04 — Preservation of canonical events
- **Procedure:** load the fixture ledger (episodes 1–2 canon). (a) Rebuild index and state twice. (b) Attempt to append a changed copy of `EV-s01e02-007` with the same ID. (c) Apply a correction. (d) Extract `negatives/contradiction_ep3.json`, in which a line asserts Dace was never injured.
- **Pass:** (a) byte-identical outputs; (b) rejected (duplicate ID); file prefix hash of `events.jsonl` unchanged throughout; (c) old event `retconned` with `superseded_by`, both retrievable, default queries return the new one; (d) a consistency `error` citing the canon event and the offending line; nothing written as canon.
- **Failing example:** any code path that edits a line in place — caught by the prefix-hash assertion and by the "only `canon_store` writes" grep test.

### T05 — Causal consistency
- **Procedure:** on fixture scripts and cards: every card after the first has `caused_by`; every event with a consequence that later events depend on appears in their `caused_by`; resolution events have an enabling plant in an earlier scene or episode; adjacent-scene connective judge (**[LIVE]**).
- **Pass:** zero uncaused scenes; zero resolutions without a prior enabling event; recursive query "what depends on EV-s01e02-007" returns the annotated set.
- **Failing example:** `negatives/deus_ex_ep3.json` — the array is fixed by a tool never mentioned before → "resolution without earlier plant".

### T06 — Evolving relationships
- **Procedure:** load deltas for episodes 1–3 (doc 05 §5.5 rows 1–3); rebuild state; lint a variant script.
- **Pass:** `C03→C02 trust` is +1 after episode 1 and 0 after episode 3, with `cause_event_id` set; state rebuild matches expected JSON; arc for C03 has the annotated steps and no skipped position.
- **Failing example:** `negatives/sudden_hostility_ep3.json` — Dace openly accuses Mara with no delta or event → "unmotivated relationship shift C03→C01".

### T07 — Season roadmap revision
- **Procedure:** (a) `python tools/replan_check.py tests/fixtures/replan_experiment.json`. (b) Property test on `replan_season` with a stub planner producing random edits. (c) **[LIVE]** `EXP-REPLAN` (doc 06 §7.4).
- **Pass:** (a) prints A `3/1/3/0`, B `0/0/0/3`, C `0/0/0/6` (**OBSERVED** on 2026-11-11). (b) No frozen or locked field ever changes; every change has `reason` and `triggered_by_event_id`; version increments by exactly one; empty delta → no new version. (c) Report exists; branch A shows ≥ 1 detected contradiction; B and C end with 0 errors and 0 unpaid season promises.
- **Failing example:** a stub proposal that edits approved episode 2 → `ValueError: episode 2 is frozen`; a proposal moving the locked log reveal → `LockedCommitmentConflict`.

### T08 — Foreshadowing and payoff
- **Procedure:** replay doc 06 §9 promise lines; run `fair_play_audit` for the mystery and `season_end_audit`.
- **Pass:** status sequence `open → developing → paid`; plant episode < development episode < payoff episode; closure recorded only with a judge "yes"; fair-play audit passes at the reveal episode (all required clues planted earlier with `audience_knows`); every red herring `abandoned_explained`.
- **Failing example:** `negatives/unpaid_clue_season.json` (episode 9 omits the stamp) → "unpaid season promise P-origin-stamp (due episode 9)"; `negatives/unplanted_payoff.json` → "payoff without earlier plant".

### T09 — Originality and repetition
- **(a) Cross-episode metrics** (`EXP-ORIG`, doc 07 §8). Pass: no flag on the calibrated thresholds for a season from the new pipeline. Passing example: two unrelated public-domain radio scripts. Failing example: an episode duplicated with names changed → opening similarity, 4-gram Jaccard, structural fingerprint and emotional contour all flagged.
- **(b) Voice separability.** 30 lines per episode, speaker labels and names removed; a judge model assigns speakers given the profiles. Pass: ≥ 70% for main cast (threshold uncalibrated). Failing example: a script where all lines were rewritten in one register.
- **(c) Framework rotation.** Objective: no framework in adjacent episodes; ≥ 3 distinct per 8.
- These measure sameness, not merit.

### T10 — Character voice consistency (audio)
- **Procedure:** render the benchmark lines for four characters with the selected engine; compute speaker-embedding cosine to each character's reference.
- **Pass:** per-character mean cosine ≥ threshold `τ_same` and minimum ≥ `τ_min`; mean cross-character cosine ≤ `τ_diff`. Thresholds are set from Kokoro's own distribution during `EXP-TTS` and recorded (they depend on the embedding model).
- **Passing example:** all lines from one fixed voice. **Failing example:** one line rendered with another character's voice → flagged as drift for the first and as a collision for the second.
- **Subjective:** blind listening A/B (doc 08 §3).

### T11 — Cinematic SFX timing
- Doc 08 §12, assertions 1–9, on `audio_scene/`. The legacy mixer must fail assertion 1. The reference sketch already demonstrates assertions 1, 2 (duck depth), 6 (peak ceiling) and 7 (**OBSERVED**).

### T12 — Full audio QA
- **Procedure:** master the fixture mix; run `audio_qa`. Negative variants: clipped stem; music bed raised 15 dB; a 5-second silent gap; mono file.
- **Pass:** final file −16 ±1 LUFS, true peak ≤ −1 dBTP, stereo, configured sample rate; exactly one lossy encode in the command log; report has no blocking findings.
- **Failing examples:** each negative variant yields its specific blocking or warning finding (clipping; speech-to-background ratio / WER delta; silence gap; channel count).

### T13 — Interrupted-job recovery
- **Procedure:** fake stages and a fake TTS engine that count invocations. (a) Raise in `write` after scene 4 of 9; rerun. (b) Kill (simulate with an exception after the atomic write) during `tts` after line 30 of 80; rerun. (c) Rerun with nothing changed. (d) Change one line's text; rerun.
- **Pass:** (a) scenes 1–4 not regenerated, 5–9 generated once; (b) 30 lines reused, 50 synthesised; (c) zero stage executions; (d) exactly one line synthesised, `mix` and `master` rerun, `write` not rerun. `job.json` is valid JSON after every interruption.
- **Failing example:** a runner that keys the cache by line index instead of content hash fails (d).

### T14 — Podcast publishing dry run
- **Procedure:** `prepare-publish` then `publish` (dry run) on the fixture episode with network access disabled in the test.
- **Pass:** `feed.xml` is well-formed; channel and item contain the tags of doc 09 §5.3; enclosure length equals the file size; GUID equals the episode ID and is unchanged on a second run; VTT parses with monotonic cues; chapters JSON has `version` and ordered `startTime`s within the duration; `dry_run.json` lists the intended host requests; no socket was opened; `rights_report.json` exists.
- **Failing examples:** an asset with `license: unknown` + `--live` → refused; a script line with XTTS as engine in a publishable show → refused; a changed GUID → test failure.

### T15 — Prompt-only creation (brief test A)
- **Procedure:** empty `books/`, empty `data/projects`, `STARDOCK_DISABLE_MEM0=1`; `create-podcast "<idea>" --yes` for each of the three one-sentence ideas; then outline and script one episode each (stub).
- **Pass:** `project.json` valid with a proposed mode (anthology / educational / serialized_fiction for the three fixtures); a bible, cast or hosts, default voices, baseline style and the mode's plan exist; no call to `epub_processor`, `reference_memory_sync`, or bible extraction (mocks assert zero calls); rendered prompts contain none of the widened franchise terms and no science-fiction wording for the horror and educational projects.
- **Failing example:** the current `ShowCreator.create_show`, which raises without ingested books.

### T16 — Style-reference isolation (brief test B)
- **Procedure:** `reference add technique_sample.txt --purpose writing_techniques` to the horror project; bind at influence 1.0 with all traits; resolve; generate cards and one scene (stub and **[LIVE]**).
- **Pass:** the stored profile validates against `StyleProfile` (closed vocabulary only); none of the sample's proper nouns appears in the profile, bindings, rendered directives, any prompt, the bible, the cast, the ledger or Mem0 writes (string search over all of them); no world or story extractor was called; **[LIVE]**: the generated scene contains none of those names and no 8-word sequence from the sample.
- **Failing example:** a stub extractor that returns `"tone": "like Captain Ysolde Varn's log"` → rejected by validation; a deliberately broken build that injects raw chunks → caught by the prompt search.
- **Limit:** this proves names, text and plot do not transfer. It does not measure stylistic resemblance.

### T17 — Multiple references (brief test C)
- **Procedure:** two sources with different profiles; binding A: influence 0.5, pacing 1.0, atmosphere 0.8, tone 1.0; binding B: influence 1.0, pacing 0.25, dialogue density 1.0, tone 0.4.
- **Pass:** resolved pacing 0.6, atmosphere 0.7, dialogue density 0.9, tone = A's value, unselected traits at baseline (the values asserted in `reference/reference_models.py`); identical result for every input order; the trace lists each source's weight and target per trait and is stored in the generation trace of the episode.
- **Failing example:** a resolver that lets the last binding win → fails order-independence.

### T18 — Unrelated shows (brief test D)
- **Procedure:** create the SF, horror and educational projects; add a reference to one; write canon, claims, Mem0 entries (fake client), voices and metrics for each; then query each store from each project.
- **Pass:** every query returns only its own project's records; a character named identically in two projects has different IDs and voices; `reference list` in one project never shows another's sources; Mem0 fake shows every call carried `project_id` and a prefixed namespace; deleting one project leaves the other two byte-identical.
- **Failing example:** today's `add_reference_material` (single `reference_materials` namespace) fails the namespace assertion.

### T19 — Reference adjustment (brief test E)
- **Procedure:** project with an approved episode 1 and a drafted, unapproved episode 2; change a binding's influence 0.25 → 0.75; run `produce-episode` for episode 2.
- **Pass:** episode 2's writing stage reruns and its prompts contain the new directives (band changed for the affected traits); episode 1's `script.json`, ledger lines, snapshot and audio hashes are unchanged; the audit log has one line with old and new values; episode 1's `reference_snapshot.json` still shows 0.25.
- **Failing example:** a runner that does not hash the resolved style → episode 2 not regenerated; a purge that rewrites the ledger → prefix-hash assertion fails.

### T20 — Disabled references (brief test F)
- **Procedure:** disable every source (`reference reset`), generate.
- **Pass:** resolved style equals the baseline exactly; prompts contain no reference-derived directive beyond the baseline and no claims or source canon sections; generation completes; nothing was deleted.
- **Failing example:** `KnowledgeContext` still injecting the old global style profile.

### T21 — Nonfiction (brief test G)
- **Procedure:** educational project with the two research sources; plan the curriculum; produce one episode (stub; **[LIVE]** optional).
- **Pass:** every stored claim has a quote found in its cited section; the two disagreeing dates are both stored as `contested` and linked; every factual statement in the script maps to a claim ID or is reported; contested and unsupported claims are voiced with an uncertainty marker (the checker looks for the attribution on the same or adjacent line); show notes list both sources; no canon extraction, belief or promise code ran.
- **Failing examples:** a script line stating the contested date flatly → "contested claim stated as settled"; a fabricated quote → rejected at extraction; a statistic with no claim → "unsupported claim".
- **Limit:** this checks traceability to the supplied sources. It does not establish that the sources are right.

### T22 — Continuing original fiction (brief test H)
- **Procedure:** the `saltmarket` project from one sentence, no references; **[LIVE]** produce three consecutive episodes with approval and replanning.
- **Pass:** T02 criteria; T03 questions written for this show answered correctly from the ledger; relationships and arc steps recorded with causes (T06 form); season roadmap versions show frozen approved episodes (T07 form); no franchise or science-fiction wording anywhere; character IDs stable across the three episodes.
- **Purpose:** shows the advanced continuity system works on an original, non-SF universe. It composes existing tests; no new mechanism.

## 5. Human review protocol

For each produced episode, the reviewer fills `episodes/<id>/quality/human_review.json`:

```json
{"reviewer": "…", "date": "…", "listened_full": true,
 "would_listen_to_next": "yes|no|unsure",
 "confusions": [{"time": "12:40", "note": "didn't know who was speaking"}],
 "continuity_errors_noticed": [], "best_moment": "…", "weakest_scene": 4,
 "audio": {"sfx_felt_integrated": 1, "speech_always_clear": 1, "notes": ""},
 "approve": true}
```

Human-noticed continuity errors that the objective checks missed become new negative fixtures.
